# 叙事与页面结构

先确定听众需要理解或决定什么，再选择表达结构。以下是可选方法，不是固定页数、页序或事实库。

## 页面结构

| 主问题 | 可选结构 |
|---|---|
| 为什么需要变化 | 趋势证据与影响机制并列 |
| 规则如何演进 | 时间线列节点，必要时增加有新信息的归纳 |
| 改善如何发生 | 相同条件下的前后对照 |
| 规模和表现如何 | 核心规模数引导，趋势与关联指标向下展开 |
| 如何建立可信度 | 身份或背景突出，经历、成果和证据分组 |
| 机制如何运作 | 输入、过程、输出依阅读顺序对应 |
| 产品有什么价值 | 功能、用户收益、真实界面逐组对应 |
| 案例说明什么 | 场景、阶段、成果、机制形成完整证据链 |
| 下阶段达到什么目标 | 期限、当前基线 → 目标值 |
| 如何实现目标 | 问题与措施对应，再展开阶段任务 |

不固定四列、双栏、金字塔、阶段数量或卡片形式。目标少时保留留白，产品界面多时让图像承载证据，不靠增加标签抢焦点。

## 标题与跨页关系

主张页标题说清结论，背景或定义页可直接命名主题。正文提供直接证据；副标题解释关键因果、定义或范围，页底结论仅在需要收束为行动时使用。

检查现状、能力依据、目标和实施路径的对应关系。目标使用前文已经说明口径的基线；任务回答如何推进。历史结果、其他场景的案例成绩与建议目标明确区分，不固定所有项目的叙事顺序。

## 图表选择

趋势用折线，分类数量用柱形，准确多字段比较用表格，演进用时间线，关系用结构图，改善用前后对比，真实能力用截图与必要标注。

统计图忠于观测值；机制示意可圆滑、不对称并有适度变化，但要标明示意。示意图不能替代实测统计，也不能伪造精确收益。比较须保留相同条件和尺度，近似值保留约数标记。
