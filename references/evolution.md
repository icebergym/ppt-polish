# 版本与规则维护

项目定稿后先提出少量可复用建议，经用户确认再写入正式规则。收到修改稿或认可某个成品，不自动等于授权把全部选择设为通用要求。已有明确授权时不重复询问。

区分通用规则、场景规则、项目例外和未确认候选。项目例外、候选证据、确认原话与来源映射只保存在用户本地项目目录；公开技能不包含这些记录。

## 更新流程

1. 阅读当前版本和适用规则，确定授权范围及需要替换的旧表述。
2. 在本地建立修改前快照：

```text
python3 scripts/version_store.py snapshot /技能目录 --note "修改前快照"
```

3. 在独立工作目录更新通用规则和必要脚本，避免重复规则，不把项目材料复制进发布目录。
4. 更新 `version.json`，记录版本、日期和通用改进；原始项目确认依据留在本地。
5. 检查链接和格式；规则使用行为场景复核，脚本执行必要测试。运行 `python3 scripts/audit_public_release.py` 并人工阅读拟公开的全部文件和提交信息。
6. 比较已安装副本和发布副本，按授权更新，再建立最终快照。

修错可用补丁版本，新增能力可用次版本，默认模式或兼容性变更可用主版本。用户明确指定同版本定稿时记录 `release_status` 与独立的 `snapshot_revision`，旧快照保持不可覆盖。

## 回退

```text
python3 scripts/version_store.py restore /快照.zip /新的空目录
```

校验文件后恢复到新的独立目录，不直接覆盖当前技能。按用户要求回退时先保留当前快照，不删除未知文件。

## 发布边界

使用专门的发布目录和文件白名单，不能整体同步私人技能目录或项目工作区。禁止提交演示稿、截图、客户数据、内部网址、个人记录、源文件名映射、缓存及历史备份。审阅当前文件与全部可达历史；只删除工作树文件不会清除历史对象。

多维护者更新前比较远端状态，避免覆盖并行改动。外部发布须有对应授权，未来项目素材不会因本次授权自动获得发布权限。
